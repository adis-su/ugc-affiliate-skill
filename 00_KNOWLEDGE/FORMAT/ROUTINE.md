# AFFILIX — Routine Format

Routine adalah format konten yang menunjukkan rangkaian aktivitas yang dilakukan secara berurutan dalam konteks kehidupan sehari-hari atau workflow berulang.

Format ini adalah **content knowledge**, bukan template wajib. Content Strategy menentukan apakah Routine sesuai untuk project.

## 1. Core Structure

Struktur dasar:

**CONTEXT → ROUTINE SETUP → STEP 1 → STEP 2 → STEP N → COMPLETION → CTA**

Routine dapat berupa:
- morning routine
- night routine
- work routine
- preparation routine
- self-care routine
- product workflow
- recurring household workflow

Nama routine harus sesuai dengan konteks yang benar-benar digunakan dalam project.

## 2. Context

Context menjawab:

**Kapan, di mana, dan untuk kebutuhan apa routine dilakukan?**

Context dapat mencakup:
- waktu
- location
- environment
- character activity
- starting state

Jangan membuat konteks yang bertentangan dengan Product Truth atau project constraints.

## 3. Routine Setup

Setup menetapkan kondisi awal.

Contoh:

**Character:** preparing for morning

**Environment:** bedroom/bathroom/workspace

**Product:** closed and placed on surface

Starting state harus jelas sebelum sequence dimulai.

## 4. Sequence

Routine terdiri dari serangkaian actions.

Setiap action sebaiknya memiliki:

**ACTION → STATE CHANGE → NEXT CONTEXT**

Contoh:

**Pick up product → Product HELD → Begin use**

Urutan harus masuk akal dan dependency antar-action harus terpenuhi.

## 5. Product Role

Jika product menjadi bagian dari routine, tentukan perannya secara eksplisit.

Product dapat:
- menjadi salah satu step
- digunakan pada titik tertentu
- menjadi preparation tool
- menjadi recurring object dalam routine

Jangan membuat routine seolah produk wajib digunakan jika hal tersebut tidak berasal dari Content Strategy atau Product Truth.

## 6. Temporal Continuity

Routine sangat bergantung pada waktu.

Perubahan dapat terjadi pada:
- time of day
- lighting
- character state
- environment state
- product state

Perubahan temporal harus disengaja.

Contoh:

**Morning → Afternoon → Evening**

Tidak boleh terjadi hanya karena generation drift.

## 7. Character State

Character State dapat berubah mengikuti aktivitas:

**SLEEPY → PREPARING → ACTIVE → COMPLETED**

Expression, gaze, pose, gesture, dan movement dapat berubah.

Character Identity tetap sama.

## 8. Environment State

Environment dapat berubah sesuai waktu atau aktivitas.

Perhatikan:
- object placement
- lighting
- surface
- background
- props
- spatial relationship

Props penting tidak boleh teleport atau berubah bentuk tanpa alasan.

## 9. Script Pattern

Routine dapat menggunakan dialogue ringan.

Struktur:

```text
HOOK
CONTEXT
ROUTINE STEP 1
ROUTINE STEP 2
ROUTINE STEP 3
REFLECTION / TRANSITION
CTA
```

Dialogue tidak harus menjelaskan setiap action secara literal.

Untuk konten visual-first, visual dapat membawa sebagian besar informasi.

## 10. Storyboard Pattern

Storyboard perlu menentukan:
- time/context
- action
- character state
- product state
- environment state
- camera
- transition
- end state

Setiap scene harus memiliki fungsi dalam sequence.

## 11. Reference System

Routine membutuhkan continuity antar-scene.

Reference harus mempertahankan:
- character identity
- outfit jika continuity mengharuskannya
- product identity
- environment
- spatial relationship
- relevant time context
- product state

Jika outfit atau environment memang berubah sebagai bagian dari timeline, perubahan harus direncanakan, bukan terjadi secara acak.

## 12. State Model

Routine dapat dipandang sebagai:

**STATE₀ → ACTION₁ → STATE₁ → ACTION₂ → STATE₂ → ...**

Contoh:

**Product CLOSED → PICK UP → HELD → OPEN → IN USE → FINISHED**

Setiap transition harus memiliki sebab.

## 13. Routine vs Tutorial

### Routine
Fokus pada **what happens in sequence**.

Audience melihat kebiasaan atau workflow.

### Tutorial
Fokus pada **how to do it**.

Audience harus dapat mengikuti instruksi.

Routine tidak perlu menjelaskan setiap langkah secara pedagogis.

## 14. Routine vs Storytelling

### Routine
Fokus pada aktivitas berulang atau workflow.

### Storytelling
Fokus pada narrative development dan story beats.

Routine dapat menggunakan storytelling, tetapi sequence aktivitas tetap menjadi struktur utamanya.

## 15. Common Failure Modes

### Random Time Jump
Waktu berubah tanpa transition.

### Outfit Drift
Outfit berubah tanpa alasan timeline.

### Product Teleportation
Product berpindah lokasi tanpa action.

### Repetitive Visuals
Semua scene memiliki framing dan action yang sama sehingga routine terasa datar.

### Unclear Sequence
Audience tidak memahami urutan aktivitas.

### Forced Product Placement
Product dimasukkan ke routine tanpa role yang natural.

### Identity Drift
Character berubah antar-scene.

### Environment Drift
Room, props, atau spatial layout berubah tanpa alasan.

## 16. Best Use Contexts

Routine cocok dipertimbangkan ketika:
- product digunakan sebagai bagian dari kebiasaan
- sequence aktivitas mudah divisualisasikan
- audience tertarik pada workflow
- context penggunaan lebih penting daripada feature explanation

## 17. CTA

CTA dapat:
- mengarahkan ke product detail
- mengajak audience melihat workflow berikutnya
- mengarahkan ke product page
- mengajak audience mempertimbangkan product dalam konteks kebutuhannya

CTA tidak boleh menyiratkan bahwa routine tersebut adalah standar universal jika sebenarnya hanya konteks kreatif.

## 18. Non-Negotiable Rules

1. Context harus jelas.
2. Sequence harus logis.
3. Setiap state change harus memiliki cause.
4. Product role harus berasal dari strategy dan Product Truth.
5. Time jump harus disengaja.
6. Character Identity tetap konsisten.
7. Environment continuity harus dijaga.
8. Jangan memaksa product masuk ke routine tanpa alasan.
9. Routine bukan otomatis tutorial.
10. Semua claim tetap tunduk pada Product Truth dan CLAIM-RULES.
