# AFFILIX — Storytelling Format

Storytelling adalah format konten yang menggunakan rangkaian narrative beats untuk membawa audience dari satu kondisi ke kondisi lain.

Format ini berfokus pada **cerita, perubahan, dan konteks**, bukan sekadar daftar fitur atau urutan penggunaan produk.

Storytelling adalah **content knowledge**, bukan template wajib. Content Strategy menentukan apakah format ini sesuai untuk project.

## 1. Core Structure

Struktur dasar:

**HOOK → CONTEXT → SETUP → DEVELOPMENT → TURNING POINT → RESOLUTION → CTA**

Tidak semua cerita membutuhkan semua beat secara eksplisit. Struktur dapat disederhanakan sesuai durasi dan tujuan content.

## 2. Hook

Hook membuka cerita dengan alasan bagi audience untuk terus mengikuti.

Hook dapat berupa:
- situasi
- pertanyaan
- problem
- observation
- unexpected moment
- statement
- visual event

Hook tidak boleh menggunakan claim yang tidak didukung Product Truth.

## 3. Context

Context menjelaskan kondisi awal.

Context dapat mencakup:
- siapa yang mengalami situasi
- di mana situasi terjadi
- kapan situasi terjadi
- apa yang sedang dilakukan
- apa yang menjadi kebutuhan atau tension

Audience harus dapat memahami dunia cerita sebelum major transition terjadi.

## 4. Setup

Setup memperkenalkan elemen penting cerita.

Elemen dapat berupa:
- character
- product
- environment
- problem
- goal
- relationship
- situation

Product tidak harus muncul pada detik pertama.

Jika product baru masuk setelah setup, kemunculannya harus memiliki narrative reason.

## 5. Development

Development memperlihatkan cerita bergerak.

Perubahan dapat berasal dari:
- character action
- discovery
- problem development
- product interaction
- environmental change
- decision
- new information

Setiap beat sebaiknya memiliki hubungan sebab-akibat.

## 6. Turning Point

Turning Point adalah momen ketika arah cerita berubah.

Contoh:
- character discovers something
- problem becomes clearer
- product enters the situation
- character changes approach
- expected action produces a new state

Turning Point harus terlihat atau terdengar secara jelas.

Jangan membuat perubahan besar hanya melalui jump cut yang tidak memiliki state bridge.

## 7. Resolution

Resolution menunjukkan kondisi setelah cerita mencapai tujuan atau titik berhenti.

Resolution tidak harus berarti:
- problem completely solved
- product is perfect
- character gets guaranteed result

Resolution hanya perlu menunjukkan hasil narrative yang sesuai dengan setup.

## 8. Product Role

Product dapat berfungsi sebagai:
- object of discovery
- tool
- part of workflow
- solution element
- subject of observation
- contextual object

Peran product harus berasal dari Content Strategy dan Product Truth.

Jangan mengubah keberadaan product menjadi bukti otomatis bahwa product menghasilkan outcome tertentu.

## 9. Character Performance

Storytelling membutuhkan performance yang mengikuti narrative beat.

Contoh progression:

**CALM → CURIOUS → CONCERNED → DISCOVERY → RELIEF**

Expression, gaze, gesture, pose, dan delivery dapat berubah sesuai scene.

Character Identity tetap tidak berubah.

## 10. Script Pattern

Storytelling script dapat menggunakan:

```text
HOOK
CONTEXT
SETUP
DEVELOPMENT
TURNING POINT
RESOLUTION
CTA
```

Script menjelaskan **apa yang ingin disampaikan**.

Dialogue menjelaskan **bagaimana karakter benar-benar mengatakannya**.

Narration dapat digunakan jika storytelling membutuhkan voice-over.

## 11. Storyboard Pattern

Storyboard harus menerjemahkan narrative beats menjadi visual.

Setiap scene dapat mendefinisikan:
- narrative purpose
- visual
- character action
- character state
- product state
- environment state
- camera
- dialogue/narration
- transition

Visual harus menunjukkan perubahan yang penting bagi cerita.

## 12. State and Causality

Storytelling sangat bergantung pada hubungan:

**STATE → EVENT → TRANSITION → NEW STATE**

Contoh:

**Product CLOSED → Character opens package → Product OPEN → Character observes contents**

Jangan melompat langsung dari state awal ke state akhir jika action di antaranya merupakan bagian penting dari cerita.

## 13. Reference System

Reference State harus menangkap kondisi penting pada narrative beats.

Reference dapat dibuat ketika:
- character enters a new important state
- product state changes
- environment changes
- camera position changes significantly
- story moves to a new location
- scene transition requires continuity

Reference bukan sekadar screenshot. Reference adalah snapshot dari state yang harus dipertahankan atau digunakan sebagai bridge.

## 14. Scene vs Story Beat

Story beat adalah **fungsi naratif**.

Scene adalah **unit visual/storytelling**.

Satu story beat dapat membutuhkan beberapa scene.

Sebaliknya, satu scene dapat membawa lebih dari satu beat jika durasi dan visualnya memungkinkan.

Jangan memaksa satu beat = satu clip.

## 15. Storytelling vs Review

### Storytelling
Fokus pada **narrative journey**.

### Review
Fokus pada **observation, assessment, dan context penggunaan**.

Storytelling dapat mengandung review elements, tetapi narrative tetap menjadi struktur utama.

## 16. Storytelling vs Problem-Solution

### Storytelling
Tidak harus memiliki problem yang diselesaikan.

### Problem-Solution
Memiliki problem dan solution sebagai struktur utama.

Problem dapat muncul dalam storytelling, tetapi tidak boleh dipaksakan jika tidak relevan.

## 17. Common Failure Modes

### Fake Narrative
Cerita terasa dibuat hanya untuk memasukkan product.

### No Causality
Scene berubah tetapi tidak jelas apa yang menyebabkan perubahan.

### Product as Magic
Product muncul lalu outcome langsung terjadi tanpa mekanisme atau evidence yang sesuai.

### Character State Jump
Emosi berubah drastis tanpa narrative trigger.

### Environment Jump
Lokasi atau spatial arrangement berubah tanpa transition.

### Overwritten Dialogue
Character menjelaskan semua hal secara verbal meskipun visual sudah menunjukkannya.

### Manufactured Testimonial
Cerita dibuat seolah pengalaman pribadi nyata padahal hanya creative scenario.

### Unsupported Resolution
Ending menyatakan hasil yang tidak didukung Product Truth.

### Identity Drift
Character atau product berubah selama cerita.

## 18. Fictional Scenario vs Factual Testimonial

Storytelling dapat menggunakan creative scenario.

Jika scenario bukan pengalaman nyata, jangan menyajikannya sebagai testimonial atau pengalaman pribadi yang faktual.

Bedakan:
- **Creative scenario:** dibuat untuk kebutuhan cerita.
- **Documented experience:** berasal dari pengalaman nyata yang diketahui.
- **Product fact:** berasal dari Product Truth.

Ketiganya tidak boleh dicampur tanpa konteks.

## 19. Best Use Contexts

Storytelling cocok dipertimbangkan ketika:
- product memiliki contextual role
- audience perlu memahami situasi sebelum product muncul
- emotional or narrative context penting
- visual progression lebih efektif daripada feature listing
- content membutuhkan character-driven presentation

## 20. CTA

CTA dapat melanjutkan narrative atau mengarahkan audience ke product.

Contoh fungsi:
- continue the story
- invite consideration
- direct to product information
- encourage exploration

CTA tidak boleh mengubah creative scenario menjadi factual product claim.

## 21. Non-Negotiable Rules

1. Story harus memiliki logical progression.
2. Setiap major transition harus punya narrative cause.
3. Character Identity tetap konsisten.
4. Product Identity tetap konsisten.
5. Product State boleh berubah hanya melalui logical interaction.
6. Storytelling tidak boleh mengarang Product Truth.
7. Creative scenario harus dibedakan dari factual testimonial.
8. Resolution tidak boleh membuat unsupported claims.
9. Dialogue tidak harus menjelaskan semua visual.
10. Reference State harus menjaga continuity antar narrative beats.
